# AQUA 并发与限流规则文档（v11.0）

> 本文档描述 v11.0 起的**现行**并发与限流行为。
> v11.0 已移除所有硬性并发限制与特殊用户覆盖机制；历史上基于
> `_SPECIAL_USER_OVERRIDES` 的个别用户并发覆盖已全部删除，不再存在。

---

## 一、现行结论：无硬性并发限制

| 项目 | v11.0 现状 |
|------|-----------|
| 硬性并发上限 | **无**。并发控制器 `try_acquire` 恒返回 True，不拒绝任何请求 |
| 用户分级额度 | **无**。不存在按注册时间或用户身份的并发分级（旧"老用户/新用户"分级机制已删除） |
| 特殊用户覆盖 | **无**。`_SPECIAL_USER_OVERRIDES` 机制已随 v11.0 移除，调度器中无此配置 |
| 限额哨兵值 | `get_limit` / `get_limit_for_user` 恒返回 `9999`（= 不限制的哨兵值） |
| 统计结构 | `get_stats()` 返回 `{"limits": {"all": 9999}, "rejected": 0, "peak": 0, "active_users": 0}`，不再有 old/new 分级字段 |

对应实现：`platform/app/concurrency.py`（并发控制器）、
`gateway/app/scheduler.py`（客户端治理算法 5/6/7）。

## 二、保留的软性机制

### 2.1 软限流排队（SoftRateLimiter）

- 位置：`platform/app/soft_limiter.py`
- 模式：**均匀间隔排队**——通过控制两次响应之间的最小间隔平滑速率
- 关键行为：**排队等待而非拒绝**，绝不因排队向客户端返回 429
- 时间戳记录点：请求**响应完成后**（`mark_response_done`），间隔从响应完成时刻起算

### 2.2 429 熔断与桶级冷却（调度器算法 4）

- 上游 429 → 该 (密钥,模型) 桶冷却 5 秒（NVIDIA 限流 1-2 秒即恢复）
- 上游 403 → 60 秒起步自适应退避（连续 403 指数增长至 600 秒）
- 上游超时 → 15 秒冷却
- 熔断器（`gateway/app/circuit_breaker.py`）：上游连续失败自动熔断防雪崩；
  全部密钥不可用时进入优雅降级而非 500
- 冷却状态只存在于 (key_id, model) 复合桶级别，无密钥级冷却路径

### 2.3 固定 IP 限流（防暴力破解，与业务并发无关）

- 登录接口：10 次/分钟/IP
- 管理接口：60 次/分钟/IP

## 三、客户端治理算法（只监测、不拦截）

调度器算法 5/6/7 仅作监测指标与统计展示，**不拒绝任何请求**：

| 算法 | 监测内容 | 阈值（仅用于标记） |
|------|----------|--------------------|
| 算法 5 客户端并发监测器 | 在途请求数（毫秒级精准追踪） | 在途 ≥ 10 标记高并发 |
| 算法 6 客户端突发率检测器 | 最近 3 秒请求时间戳队列 | 3 秒 > 20 次标记高突发 |
| 算法 7 客户端日用量监测器 | 当日累计请求数 | 无上限，每日自动重置 |

陈旧请求清理：在途请求超过 120 秒无响应视为已释放，自动回收计数
（防止客户端断连导致统计虚高）。

## 四、商用检测监控名单（AQUA_WATCHLIST）

监控名单**不再硬编码**在源码中，通过环境变量配置：

```ini
# .env —— 逗号分隔的客户端名称，不区分大小写；留空表示无监控名单
AQUA_WATCHLIST=client-a,client-b
```

- 名称匹配：小写化后精确匹配（`commercial_detect.py` 启动时读取并缓存）
- 名单内客户端在商用检测置信度达到阈值时触发更严格的标记日志
- 修改后需重启 Gateway 生效

## 五、平台控制台展示口径

- 所有用户统一显示无限制并发（哨兵值 9999 / 显示为"不限"）
- 不存在 `special_tag` / `special_reason` 等特殊用户标签字段（随覆盖机制一并移除）
- 算法 5/6/7 的监测数据（当前在途、峰值、当日用量）正常展示

## 六、变更流程

现行策略下无需为单个用户调整并发（没有可调的覆盖机制）：

1. **整体放开/收紧软限流间隔**：修改 `platform/app/soft_limiter.py` 的
   `RATE_TARGET`（当前 new 用户 120 RPM 均匀铺开），重启 Platform 生效
2. **调整监控名单**：修改 `.env` 中的 `AQUA_WATCHLIST`，重启 Gateway 生效
3. **调整桶级冷却参数**：修改 `gateway/app/scheduler.py` 算法 4 的差异化
   冷却时长，重启 Gateway 生效
